pystalk documentation¶

pystalk is a simple Python module for interacting with the beanstalk task queueing daemon. It doesn’t provide much magic, but is suitable for building all sorts of functionality on top of.

This work is available under the terms of the ISC License.

class pystalk.BeanstalkClient(host: str, port: int = 11300, socket_timeout: float | None = None, auto_decode: bool = False, connect_timeout: float | None = None)[source]¶

Simple wrapper around the Beanstalk API.

Parameters:

  • host (str) – Hostname or IP address to connect to

  • port (int) – Port to connect to

  • socket_timeout (float) – Timeout to set on the socket.

  • auto_decode (bool) – Attempt to decode job bodies as UTF-8 when reading them

  • connect_timeout (float) – Timeout to use when establishing a socket connection. Defaults to socket_timeout.

Doesn’t provide any fanciness for writing consumers or producers. Just lets you invoke methods to call beanstalk functions.

Warning

Setting socket timeout to a value lower than the value you pass to blocking functions like reserve_job() will cause errors!

class pystalk.ProductionPool(clients: List[BeanstalkClient], round_robin: bool = True, backoff_time: float = 10.0, initial_shuffle: bool = True)[source]¶

A pool for producing jobs into a list of beanstalk servers. When an error occurs, job insertion will be re-attempted on the next server in the pool.

Parameters:

  • clients – List of beanstalk client instances to use

  • round_robin – If true, every insertion will go to a different server in the pool. If false, the server will only be changed when an exception occurs.

  • backoff_time – Number of seconds after an error before a server will be reused

  • initial_shuffle – Randomly shuffle clients at initialization

All clients should have a socket timeout set or else some errors will not be detected.

NOTE: This will give you at-least-once deliverability (presuming at least one server is up), but can easily result in jobs being issued multiple times. Only use this functionality with idempotent jobs.

This method of pooling is only suitable for use when producing jobs. For consuming jobs from a cluster of beanstalkd servers, consider the pystalkworker project.

pystalk.connect_beanstalk_pool(urls: str | Iterable[str] | None = None, *, env_var: str = 'BEANSTALKD_URLS', socket_timeout: float | None = 3.0, connect_timeout: float | None = 1.0, backoff_time: float = 10.0, round_robin: bool = True, initial_shuffle: bool = True, auto_decode: bool = False, environ: Mapping[str, str] | None = None) → ProductionPool[source]¶

Build a ProductionPool for producing jobs. This is not a client.

Warning

Returns a ProductionPool, not a BeanstalkClient. The pool only implements put_job and put_job_into. It does not implement reserve_job, watch, stats, using, close, or ping. Do not swap this in for the connect_beanstalk() helpers in billing, payment, subscription-processor, or awstoken: those return a BeanstalkClient, and a silent swap fails at runtime.

connect_beanstalk() is the same function, kept as an alias so existing imports keep working. Prefer connect_beanstalk_pool().

If urls is None, the URLs are read from environ[env_var] (environ defaults to os.environ) as a comma-separated string. URLs are parsed with parse_beanstalk_urls(). Raises ValueError if the environment variable is missing or if no URLs remain after parsing. No network connections are made; constructing clients does not connect.

Parameters:

  • urls – A comma-separated string of URLs, an iterable of URL strings, or None to read from the environment

  • env_var – Name of the environment variable to read when urls is None

  • socket_timeout – Socket timeout to set on all constructed clients

  • connect_timeout – Connect timeout to set on all constructed clients

  • backoff_time – Number of seconds after an error before a server will be reused

  • round_robin – If true, every insertion will go to a different server in the pool

  • initial_shuffle – Randomly shuffle clients at initialization

  • auto_decode – Whether bodies should be bytes (False) or strings (True)

  • environ – Mapping to read environment variables from (defaults to os.environ)

Returns:

A ProductionPool for the given URLs

pystalk.parse_beanstalk_urls(urls: str | Iterable[str]) → List[str][source]¶

Parse beanstalkd URLs into a list of URIs suitable for ProductionPool.from_uris().

Accepts either a comma-separated string (e.g. the contents of a BEANSTALKD_URLS environment variable) or an iterable of strings. Each entry is stripped of surrounding whitespace and single/double quotes, empty entries are dropped, and entries without a scheme have beanstalk:// prepended (IPv6 literals such as [::1]:11300 are supported). Scheme validation is left to BeanstalkClient.from_uri().

Parameters:

urls – A comma-separated string of URLs, or an iterable of URL strings

Returns:

A list of beanstalk:///beanstalkd:// URIs

class pystalk.NoMoreClients(message: str | bytes = 'No clients can process requests at this time')[source]¶

Raised when no client in a ProductionPool can take the request.

Subclass of BeanstalkError, so except BeanstalkError also catches the all-hosts-down case. except NoMoreClients still works, including for callers that imported the name from pystalk.pool rather than pystalk. Catch NoMoreClients before BeanstalkError if the two cases need to be distinguished.

Raised with no arguments. str() is unchanged.

class pystalk.BeanstalkConnectionError(host, port, err)[source]¶

Raised when the underlying socket connection to beanstalkd fails.

Distinguishes connection-level failures (e.g. connection refused, timeout, DNS errors, broken pipe, or connection reset) from beanstalk protocol errors. Carries the host and port that were being connected to, and preserves the original socket error both on err and via exception chaining.

This is a subclass of BeanstalkError so that existing except BeanstalkError callers continue to catch connection failures.
